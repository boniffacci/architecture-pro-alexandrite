# Архитектурное решение по трейсингу

## Мотивация

Команда часто сталкивается с ситуацией, когда заказы находятся в непонятном состоянии или зависают на каком-то сервисе внутри IT-ландшафта. Проблемы с заказами могут появляться из-за потери сообщений, ошибок обработки или долгой задержки в каком-либо сервисе.  

**Зачем нужен трейсинг:**
- Позволяет отследить весь путь заказа через систему.
- Обеспечивает видимость зависших или упавших процессов.
- Упрощает выявление узких мест и проблемных сервисов.
- Позволяет собирать данные для анализа производительности и качества работы IT-систем.

**Технические метрики решения:**
1. Время обработки заказа на каждом сервисе.
2. Количество потерянных сообщений.
3. Количество повторных попыток обработки заказов.
4. Количество ошибок и падений сервисов при обработке заказов.
5. Загруженность очередей сообщений.

**Бизнес-метрики:**
1. Среднее время прохождения заказа от создания до завершения.
2. Количество заказов, находящихся в состоянии "завис" более N минут/часов.
3. Процент заказов, которые требуют ручного вмешательства.

---

## Предлагаемое решение

Для реализации трейсинга будет использована система **OpenTelemetry + Jaeger / Grafana + Prometheus + Alertmanager + ELK Stack**.  

**Компоненты, которые нужно внедрить или доработать:**
- Трейсинг на уровне микросервисов (сбор информации о каждом шаге заказа).
- Экспортер метрик для старых сервисов, которые не поддерживают OpenTelemetry.
- Хранилище логов для аналитики (ELK Stack).
- Панель мониторинга (Grafana) с видимостью пути заказа и метрик.
- Алертинг (Prometheus + Alertmanager) для уведомлений о зависших заказах.

**Схема контейнеров C4 с новыми компонентами:**
- **Зеленые элементы**: новые компоненты трейсинга (Prometheus, Jaeger, Grafana).

## Компромиссы

- Трейсинг не принесёт пользы, если:
  - Сервис проприетарный и не может отдавать метрики.
  - Реализация потребует чрезмерных затрат на доработку старого кода.
  - Заказы обрабатываются слишком быстро, и накладные расходы трейсинга превышают выгоду.
- Возможны ограничения на сбор данных из-за конфиденциальности или политики компании.

---

## Безопасность

- Внедрение аутентификации и авторизации для доступа к дашбордам и алертам.
- Доступ к системе только сотрудникам с ролью “Поддержка”.
- Защита каналов передачи метрик и логов через TLS.
- Логи и метрики хранятся с контролем доступа и шифрованием.

---

## Итог

Внедрение трейсинга позволит:
- Отслеживать полный путь заказов.
- Уменьшить количество зависших и потерянных заказов.
- Быстро выявлять узкие места в IT-системах.
- Реализовать алерты и дашборды для оперативного контроля.
