# Планирование: анализ, идентификация проблем и поиск решений

## 1. Анализ текущей архитектуры

Система компании «Александрит» состоит из трёх приложений:  

- **Онлайн-магазин** — Vue + Java Spring Boot  
- **CRM** — Vue SPA + Java Spring Boot  
- **MES** — React SPA + C# Backend  

Все приложения взаимодействуют через **RabbitMQ**, базы данных — Managed services на Yandex Cloud. CI/CD частично автоматизирован, деплой в dev — автоматический, в release/prod — ручной.  

### 1.1 Основные характеристики архитектуры

- Каждое приложение имеет один инстанс.  
- Расчёт стоимости 3D-моделей происходит синхронно в MES.  
- API для внешних заказчиков вызывает создание заказов в CRM через MES.  
- UI операторов MES показывает список заказов с фильтром и пагинацией.  

---

## 2. Выявленные проблемы

1. **Блокировка MES при обработке заказов**  
   - Сложные 3D-модели обрабатываются 2–30 минут.  
   - UI и дашборд тормозят из-за синхронной обработки.  

2. **Рост нагрузки на систему**  
   - Ежемесячный рост заказов + внешние заказы через API.  
   - Одноинстансная архитектура не масштабируется горизонтально.  

3. **Задержки и потеря заказов**  
   - Заказы от внешних API и B2C теряются или обрабатываются слишком долго.  
   - Жалобы клиентов и внешних партнёров растут.  

4. **Неэффективный дашборд MES**  
   - Пагинация и фильтры не решают проблему долгой загрузки.  
   - Операторам важно видеть новые заказы — текущая система не обеспечивает приоритет.  

5. **Ручные процессы в CRM**  
   - Подтверждение и закрытие заказов требует ручного вмешательства → замедляет поток.  

6. **Частично ручной CI/CD**  
   - Релизы в release/prod зависят от ручного деплоя, что тормозит выпуск новых версий.  

---

## 3. Инициативы по улучшению архитектуры

1. **Асинхронная обработка заказов**  
   - Вынести расчёт стоимости в отдельный worker-сервис, работающий через очередь RabbitMQ.  
   - MES и CRM получают результат асинхронно → UI не блокируется.  

2. **Горизонтальное масштабирование сервисов**  
   - Разделение frontend и backend на несколько инстансов.  
   - Использование load balancer для распределения запросов.  

3. **Оптимизация дашборда MES**  
   - Показывать только новые заказы с возможностью lazy-loading старых.  
   - Кеширование данных для ускорения загрузки.  

4. **Автоматизация CI/CD для release/prod**  
   - Настройка автоматического деплоя после успешных E2E-тестов.  
   - Минимизация человеческого фактора.  

5. **Приоритизация заказов и SLA**  
   - Ввести очереди с приоритетами: новые заказы обрабатываются раньше.  
   - Мониторинг SLA по времени обработки.  

6. **Мониторинг и трассировка**  
   - Подключение OpenTelemetry/Jaeger для всех сервисов.  
   - Метрики по времени обработки заказов, очередям, ошибкам.  

7. **Оптимизация расчёта стоимости**  
   - Внедрение кеширования частично рассчитанных 3D-моделей.  
   - Возможное использование распределённых вычислений для сложных моделей.  

---

## 4. Приоритет инициатив

| Приоритет | Инициатива | Обоснование |
|-----------|------------|-------------|
| Высокий | Асинхронная обработка заказов | Решает основную проблему блокировки MES и потерю заказов |
| Высокий | Оптимизация дашборда MES | Ускоряет работу операторов и снижает жалобы |
| Средний | Горизонтальное масштабирование сервисов | Готовит инфраструктуру к росту нагрузки |
| Средний | Автоматизация CI/CD | Сокращает задержки при выпуске новых версий |
| Средний | Приоритизация заказов и SLA | Контроль выполнения заказов по времени |
| Низкий | Мониторинг и трассировка | Удобно для анализа проблем, но не критично для бизнеса |
| Низкий | Оптимизация расчёта стоимости | Долгосрочная инициатива для ускорения сложных заказов |

---

## 5. Целевая архитектура через полгода

- **Асинхронные очереди для всех долгих операций** - MES не блокирует UI.  
- **Горизонтально масштабируемые сервисы** с load balancer - рост заказов не влияет на стабильность.  
- **Оптимизированный дашборд** - операторы видят новые заказы мгновенно.  
- **Автоматизированный CI/CD** - быстрые релизы без ручного вмешательства.  
- **Система мониторинга и трассировки** - метрики и спаны для всех критических процессов.  

---

## 6. Три приоритетных инициатив на ближайшие полгода

1. **Асинхронная обработка заказов** - ключевой блокирующий элемент, решает основную боль бизнеса.  
2. **Оптимизация дашборда MES** - повышает эффективность работы операторов и уменьшает жалобы.  
3. **Автоматизация CI/CD для release/prod** - ускоряет выпуск новых версий и сокращает задержки.  

> Эти три пункта дадут быстрый эффект на качество обслуживания заказов и уменьшение жалоб клиентов и операторов.
